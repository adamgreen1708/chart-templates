# 538-style CHART_CONFIG generation prompt (production version, renderer-aligned)

I am using a locked 538-style Python chart rendering system.

Your job is to analyse a dataset and generate a complete `CHART_CONFIG` dictionary for my renderer.

## INPUT
I will provide:
- A CSV file
- Its repo filename/path

## YOUR TASKS

### 1. Inspect the dataset structure
- Identify the correct data file path
- Identify x column
- Identify y column
- Identify whether a series column exists

### 2. DATA STRUCTURE CLASSIFICATION (CRITICAL)
Determine whether the dataset is LONG or WIDE format BEFORE generating the config.

Use `data_format = "long"` ONLY if:
- There is a real series/category column
- AND multiple observations per category
- Example: Jan, Feb, Mar across many years or multiple countries over time

Use `data_format = "wide"` if:
- The dataset is a single snapshot of categories
- OR there is only one value per category
- Example: Jan–Dec for a single year
- Example: country ranking, league table, category comparison

IMPORTANT:
- If using `wide`, DO NOT include `series_col` or `value_col`
- If using `long`, you MUST include both `series_col` and `value_col`
- Never set `series_col = None` in a long chart
- If the dataset is a single snapshot, it is almost always `wide`

### 3. Choose the best chart type
- `line` → time series / continuous trend
- `bar` → category comparison
- `dot` → ranked comparison
- `scatter` → relationship between two numeric variables

### 4. CHART TYPE DECISION (STRICT)
You must explicitly decide which story the data represents before choosing the chart:

- Trend over time → `line`
- Ranked comparison (best to worst) → `dot` preferred, or ranked `bar`
- Category comparison in natural order (e.g. Jan–Dec) → `bar`
- Relationship between two numeric variables → `scatter`

IMPORTANT:
- Do NOT choose `line` unless x is time or an ordered sequence
- If the dataset is a single snapshot of categories, DO NOT use `line`
- If the story is ranking, prefer `dot`
- If categories have a natural order (e.g. Jan–Dec), preserve that order and do NOT sort
- If you use `dot`, it must be a ranking story
- If you want a ranked bar, set `chart_type = "bar"` and `sort_descending = True`

### 5. Identify the strongest single story in the data
Choose one dominant narrative:
- trend
- ranking
- comparison
- outlier
- change

Avoid generic summaries.
Pick the clearest editorial story the renderer can support cleanly.

### 6. Decide whether annotations are needed
- `reference_lines` only if genuinely useful
- `highlight_points` only if exact coordinates are known
- `annotate_points` only if exact coordinates are known
- `auto_end_labels` usually preferred except for scatter

If exact coordinates are uncertain, leave annotations empty.

## CHART-TYPE-SPECIFIC RULES

### Line charts
- Must use `data_format = "long"`
- Must include `series_col` and `value_col`
- Use `focus_series` if a single series is the story
- Keep `sort_descending = False`
- Use for time or ordered-sequence trends only

### Bar charts
- Must use `data_format = "wide"`
- Do NOT use `series_col` or `value_col`
- Use calendar/natural order unless explicitly ranking
- Ranked bar is allowed by setting `sort_descending = True`
- Bar charts may use `auto_end_labels = True`
- In bar charts:
  - `x_col` = category column
  - `y_col` = numeric value column

### Dot charts
- Must use `data_format = "wide"`
- Must include `sort_descending = True`
- Used for ranked comparisons only
- Do NOT use `series_col` or `value_col`
- Keep `x_col` as the category column
- Keep `y_col` as the numeric value column
- The renderer will plot:
  - categories from `x_col` on the y-axis
  - numeric values from `y_col` on the x-axis
- `auto_end_labels` may be True
- The standard fields `y_axis_min`, `y_axis_max`, `y_tick_interval`, and `y_tick_format` must still be included
- For dot charts, those standard axis fields control the numeric value axis used by the renderer

### Scatter charts
- x and y must both be numeric
- Set `auto_end_labels = False`
- Only annotate meaningful standout points with exact coordinates
- Use only when the story is a relationship between two numeric variables

## CRITICAL RULES

- Do not invent values
- Any `highlight_points` and `annotate_points` must match real data exactly
- If unsure, leave them empty
- Never use `data_format = "long"` without valid `series_col` and `value_col`
- Never set duplicate keys in the output
- If the dataset is a single snapshot, it is almost always `wide`
- If the renderer cannot support the editorial idea cleanly, change the story
- Use only config structures the renderer can actually handle
- Do not force a line chart onto categorical snapshot data
- Do not force a dot chart onto natural-order category stories unless you are explicitly changing the story to ranking

## ALWAYS INCLUDE THESE STANDARD FIELDS IN EVERY CHART_CONFIG
Always include these keys explicitly:

- `"y_axis_min": 0`
- `"y_axis_max": None`
- `"y_tick_interval": 25`
- `"y_tick_format": ".0f"`
- `"auto_end_labels": True` for line/bar/dot
- `"auto_end_labels": False` for scatter
- `"sort_descending": False` unless chart is dot or a ranked bar

Do not omit these fields.

## OUTPUT REQUIREMENTS
Return:

1. Short explanation (max 4 lines)
   - chart type chosen
   - data format chosen
   - key story

2. A valid Python dictionary called `CHART_CONFIG`

## REQUIRED OUTPUT SHAPE
The config must always explicitly include:

```python
"y_axis_min": 0,
"y_axis_max": None,
"y_tick_interval": 25,
"y_tick_format": ".0f",
"auto_end_labels": True,   # or False for scatter
"sort_descending": False,  # or True for dot / ranked bar
