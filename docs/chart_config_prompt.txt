# 538-style CHART_CONFIG generation prompt (updated)

I am using a locked 538-style Python chart rendering system.

Your job is to analyse a dataset and generate a complete `CHART_CONFIG` dictionary for my renderer.

## INPUT
I will provide a CSV file and its repo filename/path.

## YOUR TASKS

1. Inspect the dataset structure.
   - Identify the correct data file path I provide
   - Identify x column
   - Identify y column
   - Detect whether a series column exists

2. Choose the best chart type:
   - `line` → time series / continuous trend
   - `bar` → category comparison
   - `dot` → ranked comparison
   - `scatter` → relationship between two numeric variables

### CHART TYPE DECISION (STRICT)

You must explicitly decide which of these four stories the data represents BEFORE choosing the chart:

- Trend over time → use `line`
- Ranked comparison (best to worst) → use `dot` (preferred) or `bar`
- Category comparison (unordered or natural order like months) → use `bar`
- Relationship between two numeric variables → use `scatter`

IMPORTANT RULES:
- Do NOT choose `line` unless the x-axis is time or ordered sequence
- If the dataset is a single snapshot of categories (e.g. months in one year), DO NOT use `line`
- If the story is ranking, prefer `dot` over `bar`
- If categories have a natural order (e.g. Jan–Dec), preserve that order (do NOT sort)

3. Identify the strongest single story in the data.

4. Decide whether annotations are needed:
   - `reference_lines` only if genuinely useful
   - `highlight_points` only if there is a clear standout point
   - `auto_end_labels` should usually be used instead of manual end labels

5. Generate a full `CHART_CONFIG` dictionary using the exact schema below.

## CRITICAL RULES

- Do not invent values.
- Any `highlight_points` and `annotate_points` must match real data coordinates exactly.
- If you are not confident in the exact coordinates, leave those arrays empty.
- For long-format single-series charts, explicitly set `focus_series`.
- `focus_series` can be a string or a list.
- `secondary_series` can be a string or a list.
- Do not force a multi-series story if a single-series story is cleaner.
- If the renderer cannot support the editorial idea cleanly, change the story.
- For `bar` charts:
  - Preserve natural category order unless the story is ranking
  - Use `sort_descending = True` only when the story is explicitly “highest vs lowest”

- For `dot` charts:
  - Always sort descending
  - Use for ranked comparisons instead of bar where possible

- For non-line charts:
  - Do not use `focus_series` or `secondary_series`

## REQUIRED OUTPUT FORMAT

Return:
1. A short explanation (max 4 lines)
2. A full Python dictionary called `CHART_CONFIG`
