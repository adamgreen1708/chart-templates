# 538-style CHART_CONFIG generation prompt (FULL HOUSE VERSION)

I am using a locked 538-style Python chart rendering system.

Your job is to analyse a dataset and generate a complete `CHART_CONFIG` dictionary for my renderer.

## INPUT
I will provide:
- a CSV file
- its repo filename/path

## YOUR TASKS

### 1. Inspect the dataset structure
Identify:
- the correct data file path
- x column
- y column
- whether a series column exists

### 2. Classify the data structure
Use `data_format = "long"` ONLY if:
- there is a true series/category column
- and there are multiple observations per series

Use `data_format = "wide"` if:
- the dataset is a single snapshot of categories
- or there is only one value per category
- or the chart is scatter with numeric x and numeric y

Rules:
- if using `wide`, set `"series_col": None` and `"value_col": None`
- if using `long`, you MUST include `"series_col"` and `"value_col"`
- never omit these keys

### 3. Choose the best chart type
- `line` → time series / continuous trend
- `bar` → category comparison
- `dot` → ranked comparison
- `scatter` → relationship between two numeric variables

### 4. Chart type decision (strict)
- trend over time → `line`
- ranked comparison → `dot` preferred, or ranked `bar`
- category comparison in natural order → `bar`
- relationship between two numeric variables → `scatter`

Rules:
- do NOT choose `line` unless x is time or ordered sequence
- if the dataset is a single snapshot of categories, do NOT use `line`
- if the story is ranking, prefer `dot`
- if categories have a natural order, preserve that order and do NOT sort
- if you want a ranked bar, set `"chart_type": "bar"` and `"sort_descending": True`
- ranked bar charts should be horizontal

### 5. Identify the strongest single story
Choose ONE dominant narrative:
- trend
- ranking
- comparison
- outlier
- change
- relationship

### 6. Decide whether editorial helpers are needed
Actively consider:
- a benchmark or average reference line
- a highlight point for a standout maximum, minimum, or outlier
- a short annotation for a major turning point, outlier, or top-ranked category

Only include these when exact coordinates are known.

### 7. House style rules (critical)
All charts must be generated for a square, mobile-friendly output.

Use these defaults unless there is a strong reason not to:
- `"fig_width": 8.0`
- `"fig_height": 8.0`
- `"title_fontsize": 22`
- `"subtitle_fontsize": 13`
- `"tick_label_fontsize": 12`
- `"footer_fontsize": 10`

Headlines and subtitles must be kept short enough to fit a square layout.
You MUST also include:
- `"title_wrap_width": 28`
- `"subtitle_wrap_width": 56`
- `"title_max_lines": 2`
- `"subtitle_max_lines": 2`

Spacing / margins must be:
- `"title_x": 0.10`
- `"title_y": 0.93`
- `"subtitle_x": 0.10`
- `"subtitle_y": 0.855`
- `"footer_left_x": 0.10`
- `"footer_right_x": 0.90`
- `"footer_y": 0.075`
- `"plot_top": 0.72`
- `"plot_bottom": 0.15`
- `"plot_left": 0.10`
- `"plot_right": 0.90`

This is to ensure:
- square render proportions
- shorter headers and subheaders
- visible space between title and subtitle
- consistent right-hand border and padding on all sides

## CHART-TYPE-SPECIFIC RULES

### Line charts
- must use `data_format = "long"`
- must include `"series_col"` and `"value_col"`
- use `focus_series` if a single series is the story
- keep `"sort_descending": False`

### Bar charts
- must use `data_format = "wide"`
- must set `"series_col": None` and `"value_col": None`
- use natural order unless explicitly ranking
- ranked bar is allowed by setting `"sort_descending": True`

### Dot charts
- must use `data_format = "wide"`
- must set `"series_col": None` and `"value_col": None`
- must include `"sort_descending": True`

### Scatter charts
- must use numeric x and numeric y
- should usually use `data_format = "wide"`
- must set `"auto_end_labels": False`, `"sort_descending": False`, `"series_col": None`, `"value_col": None`
- if a relationship exists, include `"show_regression_line": True` and `"show_r_squared": True`
- if a regression line is shown, you MUST highlight the point with the largest deviation from the regression line and you SHOULD annotate it

## CRITICAL RULES

- do not invent values
- highlight_points and annotate_points must match real data exactly
- if unsure, leave them empty
- never use `data_format = "long"` without valid `"series_col"` and `"value_col"`
- never set duplicate keys in the output
